# QA Engineer · Senior Level 1 (L6) · Contentful

**Location:** LATAM, remote

A senior QA engineer for a US-based global travel company's move from a legacy enterprise CMS to Contentful: quality gates for a new Next.js front end and for a phased migration of four partner-facing websites.

## Must have

- [ ] 5+ years of experience in software development or quality engineering `[HR job description]`
- [ ] Test strategy and planning `[handbook role]`
- [ ] End-to-end test automation with Playwright `[handbook role]`
- [ ] Performance testing with Lighthouse CI `[handbook role]` `[Propuesta]`
- [ ] Accessibility testing with axe `[handbook role]`
- [ ] Component and unit testing with Jest or Vitest and Testing Library `[handbook platform]`
- [ ] Has owned a project's quality architecture decisions (test pyramid, tooling, coverage strategy) `[handbook level]`
- [ ] Has validated a content migration between CMSs: counts, required fields, broken links and visual comparison `[Propuesta]`
- [ ] English B2 or higher `[suite rule]`

## Nice to have

- SEO and analytics parity checks (titles, canonicals, redirects, data layer) `[Propuesta]`
- Testing multilingual sites across locales and breakpoints `[Propuesta]`
- Testing headless CMS front ends: preview vs published content, cache revalidation `[Propuesta]`
- Familiarity with Adobe Experience Manager, the migration's source platform `[Propuesta]`

## What the person will do

- Define the test strategy and quality gates for the front end and the migration `[handbook role]` `[handbook level]`
- Build and maintain automated suites: end-to-end, accessibility and performance, with Lighthouse thresholds that stop a build `[handbook role]` `[Propuesta]`
- Validate each migration run and each site's ramp (20%, 50%, 100%), feeding the go/no-go decisions `[Propuesta]`
- Check SEO and analytics parity with the current sites `[Propuesta]`
- Track quality metrics and regressions, and triage bugs with frontend and backend `[handbook role]`

## Screening

1. "How did you define the test strategy on your last project?" A good answer mentions the test pyramid, tooling choices and coverage targets they set.
2. "Which Playwright, Lighthouse CI and axe checks did you run in a pipeline?" A good answer mentions end-to-end suites, performance thresholds that block a build, and automated accessibility checks.
3. "How did you verify that a content migration was complete and correct?" A good answer mentions counts, required fields, broken links and visual comparison between old and new pages.
4. Check in the CV or profile: 5+ years of experience, test automation on a web front end, and component tests with Jest or Vitest.
5. Check: English at B2 or higher, in the screening call.

## Not a fit if

- Under 5 years of experience.
- Has only executed test cases, never defined a test strategy.
- Has never automated end-to-end tests with Playwright.
- Has never run Lighthouse CI or axe checks.
- Has never written component or unit tests with Jest, Vitest or Testing Library.
- Has never owned a project's quality architecture decisions.
- Has never validated a content migration.
- English below B2.
