# Backend Developer · Semi Senior Advanced (L5) · Contentful

**Location:** LATAM, remote

A backend developer for a US-based global travel company's move from a legacy enterprise CMS to Contentful: the content models, the migration pipeline for four partner-facing websites, and a content API that serves the same content to email marketing and CRM channels.

## Must have

- [ ] 4+ years of experience in software development `[HR job description]`
- [ ] Server-side development fundamentals and backend testing (unit and integration) `[handbook role]`
- [ ] Content modeling in Contentful, with the Content Management API (CMA) and `contentful-cli` `[handbook role]` `[handbook platform]`
- [ ] REST/GraphQL API design and consumption, including the Contentful Content Delivery API or GraphQL Content API `[handbook role]` `[handbook platform]`
- [ ] Has owned multiple related integrations, or a content model with cross-cutting dependencies (multiple content types, multiple systems) `[handbook level]`
- [ ] Has built content migration scripts between CMSs: extract, transform, load and validate, with repeatable runs `[Propuesta]`
- [ ] Has built a Contentful app or a custom API service that other systems consume `[Propuesta]` `[hiring lead]`
- [ ] English B2 or higher `[suite rule]`

## Nice to have

- Familiarity with Adobe Experience Manager (Sites, Content Fragments, Assets), the migration's source platform `[Propuesta]`
- Integration with Salesforce Marketing Cloud (content pushed to SFMC and rendered at send time) `[Propuesta]` `[hiring lead]`
- Search integration with Contentful (Algolia or Elasticsearch) `[handbook platform]` `[hiring lead]`
- Multilingual content: Contentful locales and fallback logic `[Propuesta]`
- Contentful webhooks driving downstream processing (queues, cache revalidation) `[Propuesta]`

## What the person will do

- Implement the Contentful content types for the partner web pages, sections and blocks, and for the channel content `[handbook role]` `[Propuesta]`
- Build and run the migration pipeline from the legacy CMS: idempotent loads by a stable ID, and validation on every run (counts, required fields, broken links) `[Propuesta]`
- Build the content API as a Contentful app: variant resolution by locale, tone and channel, fallback to default content, and one trace record per resolution `[Propuesta]` `[hiring lead]`
- Integrate the content API with the email marketing platform, keeping its content current on every change `[Propuesta]` `[hiring lead]`
- Build editor apps for checks that span several entries and for custom approval workflows `[Propuesta]`
- Write unit and integration tests, and agree API contracts with the frontend developers and deployment needs with DevOps `[handbook role]`

## Screening

1. "Describe a content model you built in Contentful and how you created or changed it." A good answer mentions content types and references, the CMA or `contentful-cli`, and migrations across environments.
2. "How did you migrate content from one CMS to another?" A good answer mentions extract, transform, load and validate steps, and runs that can be repeated without duplicating content.
3. "Tell me about a Contentful app or API service you built that other systems consumed." A good answer mentions the API contract, error handling and tests.
4. Check in the CV or profile: 4+ years in software development, with backend work on a headless CMS and integrations across several systems.
5. Check: English at B2 or higher, in the screening call.

## Not a fit if

- Under 4 years of software development experience.
- Has no server-side development or backend testing experience.
- Has never modeled content in Contentful through its Management API or CLI.
- Has never designed or consumed REST/GraphQL APIs.
- Has only worked on single, isolated features, never on several related integrations or a cross-cutting content model.
- Has never written content migration scripts.
- Has never built a Contentful app or an API service consumed by other systems.
- English below B2.
