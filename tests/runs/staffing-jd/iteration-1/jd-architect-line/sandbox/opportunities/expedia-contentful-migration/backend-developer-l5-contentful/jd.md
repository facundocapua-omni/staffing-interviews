# Backend Developer · Semi Senior Advanced (L5) · Contentful

**Location:** LATAM; remote

A backend developer for a US-based global travel company's move from Adobe Experience Manager to Contentful: builds the content model, the migration pipeline, Contentful apps and a content resolution API that feeds Salesforce Marketing Cloud.

## Must have

- [ ] 4+ years of software development experience `[HR job description]`
- [ ] Server-side and platform development fundamentals `[handbook role]`
- [ ] Content modeling: content types, references and locales `[handbook role]` `[Propuesta]`
- [ ] REST and GraphQL API design and consumption `[handbook role]`
- [ ] Backend testing `[handbook role]`
- [ ] Contentful Content Management API, `contentful-cli`, and the Content Delivery or GraphQL Content API `[handbook platform]` `[Propuesta]`
- [ ] Contentful App Framework: apps in the editor and app-hosted services `[handbook platform]` `[Propuesta]` `[hiring lead]`
- [ ] Owns several related integrations, or a content model with cross-cutting dependencies, end to end `[handbook level]`
- [ ] Third-party integrations: authentication, data mapping, errors and retries `[handbook level]`
- [ ] Scripted content migration: extract, transform, load and validate, run repeatedly `[Propuesta]`
- [ ] English B2 or above `[suite rule]`

## Nice to have

- Salesforce Marketing Cloud integration `[Propuesta]` `[hiring lead]`
- Adobe Experience Manager: content structure, Content Fragments and content extraction (the migration's source platform) `[Propuesta]`
- Search integration with Algolia or Elasticsearch `[handbook platform]` `[hiring lead]`
- Contentful webhooks and environments for content model migrations `[Propuesta]`
- Translation connectors for Contentful `[Propuesta]`

## What the person will do

- Model the content types for pages, sections and blocks, mapped from the legacy components `[handbook role]` `[Propuesta]`
- Build the migration pipeline: extract from the legacy CMS, transform to the new content types, load idempotently by a stable ID, and validate counts, required fields and links on every run `[Propuesta]`
- Build the content resolution API as a Contentful app: variants by locale, tone and channel, fallback to default content, and one trace record per resolution `[Propuesta]` `[hiring lead]`
- Integrate the API with Salesforce Marketing Cloud, keeping a Marketing Object current on every content change `[Propuesta]` `[hiring lead]`
- Build editor apps for cross-entry checks and a custom per-locale approval workflow `[Propuesta]`
- Write unit and integration tests for backend logic `[handbook role]`
- Agree API contracts with Frontend and runtime needs with DevOps `[handbook role]`

## Screening

1. "How have you modeled content in Contentful, and how did you change the model once authors were using it?" A good answer mentions content types and references, locales, and migrations run through the CMA or `contentful-cli` in a separate environment.
2. "Describe a content migration you built." A good answer mentions a repeatable script, mapping to the new model, re-runs without duplicates, and validation.
3. "Have you built a Contentful app?" A good answer mentions the App Framework, locations in the editor, and where the app's logic runs.
4. Check in the CV or profile: 4+ years of backend work, with at least one headless CMS project that includes content modeling or migration.

## Not a fit if

- Has used Contentful only from the front end, never through the Management API
- Has no content modeling or content migration experience
- Has fewer than 4 years of backend experience
- English below B2
