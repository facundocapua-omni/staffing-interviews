# Expedia: AEM to Contentful migration

## Context

- **Client:** Expedia Group (EG); external. Sold by Globant's Salesforce Studio.
- **Project:** migrate EG's partner web from Adobe Experience Manager to Contentful, with a new Next.js front end on EG's AWS, and build a Content Resolution API that serves Contentful content to Salesforce Marketing Cloud.
- **Workstreams:**
  - Partner Web Content: Contentful setup and custom development (live preview, custom workflow app, editor apps), a Next.js front end on OpenNext in EG's AWS account, Akamai routing during the migration, a scripted content migration pipeline for four sites (partner.expediagroup.com, host.vrbo.com, escapia.com, expediagroup.com; 102,585 items), and training. 12 months, Nov 2026 → Oct 2027. Staffed by the Labor Estimate's lines.
  - Content Resolution API: a runtime service deployed as a Contentful app, which resolves variants by locale, tone and channel with fallback, pushes content to an SFMC Marketing Object, takes NBA's decision payload, and writes one trace record per resolution. 8 weeks in the Proposal; billed Aug–Sep 2027 in the SOW. Staffed by the same backend people as Partner Web (intake answer 6).
- **Dates:** Nov 2026 → Oct 2027. Month 1 = Nov 2026 (the SOW's first billing date is 2026-11-30; the Proposal's "Team Integration (Nov-1)").
- **Stack signals:**
  - Content platform: Contentful (organisation, spaces, locales and fallback, environments, workflows and tasks, scheduled publishing, Live Preview, App Framework apps in the editor, Contentful Personalization depending on the tier); translation via Babel Prime or a supported connector, still to decide.
  - Front end: Next.js (App Router) and Tailwind, deployed with OpenNext to EG's AWS account; component library from Figma designs on EG's design system (EGDS 1 or 2, to confirm); ISR regenerated by the publish webhook, SSR for private sections, Draft Mode preview domain; locale routing and hreflang; SEO and analytics parity.
  - AWS and delivery: server, image and revalidation Lambdas, S3 page cache, DynamoDB tag cache, SQS revalidation queue, CloudFront or ALB or function URL as origin; IAM, networking, WAF; IaC with SST, Terraform or CDK; GitHub Actions or equivalent with Lighthouse thresholds; Datadog and CloudWatch.
  - Edge: Akamai and Cloud Gate Proxy, routing by path and cohort, redirects, cache purge.
  - Migration: extract from AEM, transform, idempotent load by stable ID, validation (counts, required fields, broken links, visual diff), phased ramps 20/50/100%.
  - API: Contentful app, SFMC Marketing Object, NBA decision payload, EG's log system.
- **Locations:** P&L lines in Colombia, Mexico, Peru, Spain and the USA. JDs: remote, open to all of LATAM (intake answer 11).

1. Which lines get a JD? **Answer:** only the six technical lines, 4 to 9. Lines 1–3 are already assigned or are structure.
2. Do the Martech Content Specialist lines (off-handbook role) get a JD? **Answer:** no. A P&L lists the whole team; intake keeps only DXP technical roles.
3. Which sheet sets seniority? **Answer:** the Labor Estimate.
4. Level equivalence. **Answer:** Mid Level → L5 (Semi Senior II, 4 years); Sr → L6 (Senior I, 5 years); Sr Level 2 → L7 (Senior II, 6 years); Sr 3 → L8 (Tech Lead I / II, 7+ / 10+). Globant `Lead` and Experience Senior I / II stay unmapped.
5. Platform: the P&L role label or the Proposal's technology? **Answer:** the Proposal's technology, Contentful. "AEM Backend Developer" is only today's catalog name.
6. Is the Content Resolution API staffed by the Partner Web people, and do its needs fold into their JDs? **Answer:** the same backend people; its needs (SFMC, Contentful App) become Requirements of the backend JDs (lines 4 and 5).
7. Allocation. **Answer:** irrelevant to the JD, which sources a profile.
8. English. **Answer:** B2 minimum for every Position; a B1 exception is possible for a role that does not face the client. No exception was granted, so every JD states B2.
9. Line 4 (Sr 3, Client's Role Name "Architect"): Expert or Tech Leader? **Answer:** Expert. Mapped to the Software Architect HR job description (11 years). The question of whether the person leads people no longer applies: the Expert has no reports.
10. The handbook's Contentful search integration (Algolia / Elasticsearch). **Answer:** Nice to have.
11. Location. **Answer:** remote, open to all of LATAM.
12. Does the Content Resolution API's QA (the SOW's AEM QC Analyst line for the API) fold into the QA JD? **Open:** answer 6 covered the backend only. Waiting on it: any API testing Requirement in `qa-engineer-l6-contentful/jd.md`, which today covers Partner Web only.
